## Recent analysis state

- Traffic reactivation: `CheckAIVehicleReactivation` dispatches traffic flag `+0x200 & 0x10` through the tick/countdown/cap gate; police flag `+0x20` bypasses that cap. This is a reactivation decision, separate from roster allocation. `g_nInactiveAIVehicleCount` is shared across traffic, police, opponent and nonlocal vehicle-controller paths, so `g_nTrafficVehicleCount - g_nInactiveAIVehicleCount` is not established as a traffic-only active or visible count. Ghidra dispatcher/global comments and detailed notes were saved and audited.
- Knockout progression: `EliminateLastEligibleResultAndUpdateOrder` clears/ranks the 16-entry profile tables, may clear eligibility and set vehicle field `+0x2c4`, then increments the WORD progression unconditionally. Direct profile indexing has no local bounds check. Its only direct caller is gated by the result path; invocation count and valid profile-ID domain remain unknown.
- Race roster initialization: all four roster builders zero the same opaque eight-byte region at `006fd394`; it is now named and typed `g_abRosterBuildClearedRegion: byte[8]`. The direct callers establish initialization only; purpose and indirect consumers remain unknown. Details are under issues #5–#6 in `analysis/detailed-analysis-notes.md`.
- Race roster budgets: the ordinary race count selector is a menu code (`None`, `One`, `Full Grid`), not an arbitrary count. Builders use nominal eight-slot formulas, but those formulas do not establish array capacity. Network paths derive setup records from advertised roster state, with some modes limiting matching IDs through an eight-entry map; upstream admission and total storage bounds remain open.
- Cross-system flag: `g_bCrossSystemFeatureFlags & 0x20` changes Hot Pursuit roster budgets/skill and other AI/traffic/roadblock paths, but the mapped byte is0. In `CalculateAISpeedIndexedAcceleration`, the branch also requires vehicle flags `+0x200 & 0x20` and vehicle float `+0x7c4 > 20.0`, then scales acceleration by0.5; threshold and scale are typed/named doubles in Ghidra. The `+0x7c4` value is a sign-selected magnitude-like track-axis speed scalar (`+0x7c0` is a velocity/track-axis dot product); a participant-measurement formatter applies mph/km/h-like factors, supporting m/s only if the axis is normalized. Placement normalizes packed basis rows, but then replaces them with the track-query basis without a following normalization, so20 m/s remains a qualified static inference, not runtime-validated. Persistent Ghidra lists46 direct read references and no direct writer; REA lists45 and omits `0043f830`. Persistent Ghidra shows `0x10` there sets `g_nRaceMode=3` in one transport-menu callback path; provider discrepancy and user-facing meaning remain unresolved. Runtime reachability and ownership are open. This flag differs from the selected Normal/Aggressive AI skill; see issue #5 notes.
- Police stop escalation: `ResetVehicleAIAndPursuitFields` clears target-state `+0x2c8`; `FinalizePoliceStop` increments it, compares it with `g_nPursuitStopLimit`, then uses the new stop count to index the ten-row, 16-byte escalation table at `005521ac`. `BuildHotPursuitRoster` sets the limit to lap count+1 for racers/network sessions, but1 for local police and split-screen dual-police. The HUD's “Busted” threshold is limit-1 under its linked non-police-view gate; terminal state uses count>=limit. The table ends at `0055224b`, before the police voice map; no local index clamp is present. Other object types use offset `+0x2c8` for unrelated data, so keep this meaning scoped to the target-state record. See issue #10 in `analysis/detailed-analysis-notes.md`.
- Track selection: the nine-row `TrackAIParameterRecord` table is a tuning table, not proof of nine selectable slots or capacity. Menu tracing establishes IDs 0–7 in the series map plus an explicit unlock path for ID 8. The shared selector has network and encoded writers without local normalization, and reviewed race-load wrappers format/use it without a local range check; lower-layer rejection, reachability and runtime consequence remain unresolved. Details are in the issue #8 section of `analysis/detailed-analysis-notes.md`.
- Post-race records: `UpdateStoredRecordsFromVehicleResult` now names/types its vehicle pointer, returned update mask and minimum nonzero lap value. Result-bit meanings and timing units remain unverified; see the stored-record and issue #7 notes.
- Lap/race-state finalization: `FinalizeRaceVehicleStates` applies caller-supplied fallback status values across player and AI-category lists, while preserving observed states 3 and 4 under specific gates. The race-completion call passes EAX=3; numeric states are not a full enum. The lap-estimate initializer's double constants are now named and typed: 6.0 scales track segments and 64.0 multiplies the estimate numerator; units remain unknown. The lap-metric popup now has typed/named locals; its highlight index is uninitialized if no positive metric is found. Details and REA evidence are in the issue #7 section of `analysis/detailed-analysis-notes.md`.
- Controller input: `RunRaceInputCollectionWorker` at `0041d7e4` gathers bound input after event signals; shutdown signals it without joining. `g_dwInputActionMaskHistory[32]` supports held/edge checks; static callers map some ordinals to viewport, HUD, audio and preset routines. Held ordinals `0x15`/`0x17` feed `g_anViewportHeldActionResults[2]` for viewport/render consumers, while exact control and visual labels remain unknown. Ordinal `0x09` reaches a selector cycling modulo4 for prior values0–3, relevant to optional preset issue #16. `RunRaceLoop` skips stale rows when its watermark lags by more than16. Physical bindings, counter-wrap behavior, runtime cadence and teardown remain open; see issue #14 notes.
- Issue #13: a reproduced EA PlayStation manual documents Arcade/Simulation styles and per-equipped-car ABS ON/OFF; the Windows manual distinguishes braking assist and traction assist but does not list ABS in its assist menu. PC code has a conditional per-car `usesanti` response path, not yet a proven user-facing style/ABS toggle. REA confirms nine `CED04DBG` labels in a consecutive pointer table, but no direct code xrefs target its slots; indexed consumers remain possible. Cases16–30 of the unfunctioned 80-target dispatch now map parser keys/field IDs to scalar, byte and eight-element array comparisons. Float cases test ZF after x87 status transfer, so equal and unordered outcomes both match. REA still finds the dispatch and candidate entry outside recognized procedures, with no direct incoming reference to the dispatch instruction. Caller, compared-record identities, result-array contract, and remaining cases are unresolved; see detailed notes and Astra backlog.
- Serial/COM and modem: static tracing connects the COM1–COM4 menu values to the type-3 serial provider, `\\.\COM%d` opening, overlapped ring I/O, and the type-3/type-6 modem callbacks. `SerialPortIoRecord.command` is typed in Ghidra as a four-byte enum for values0–4; all six resolved direct callers of its setter use those values. Registration publishes a new record before setting command1, and the worker first reads the field outside its lock; an overlapping scan could see allocator-dependent bytes, though no bad value or runtime failure is established. A bounded scan of 15 functions with direct table references found base+0 stores in the setter and worker clear; registration was checked separately. The reference manager omits its indexed table store, so direct field writes or indirect producers remain unexcluded. Other nonzero values have no dedicated purge/close branch, and purges are asynchronous requests. The TAPI line callback at `004f9500` has a six-argument `__stdcall` signature and partial message enum; session status, open signal, active provider record, application/line/call/comm handles, and selected device ID `g_dwSelectedTapiDeviceId: uint` are named/typed. Its image sentinel is `0xffffffff`; the device ID is distinct from the menu's modem-list ordinal and is passed to TAPI negotiation/open/configuration. A nonzero Type-6 setup failure can bypass the worker's only direct signal-clear store while the opener waits without a local timeout; this is a conditional static liveness candidate, not a confirmed hang. First-port startup has another conditional lost-wake candidate: the worker's wrapper resumes and yields without a ready handshake, while the worker creates its initially nonsignaled event before registration's first signal. The last-port release path at `0051b2c8` may also fail to wake the worker after its record slot is cleared. These startup/shutdown orderings are static scheduling candidates, not confirmed hangs; test both in Astra/runtime. Saved Ghidra xrefs show no other direct references to the worker wake-event handle; aliases or indirect access remain possible. Exact TAPI event meanings, UI callback reachability, device lifecycle, lock/worker teardown and real hardware behavior remain unresolved; see the serial and modem sections in `analysis/detailed-analysis-notes.md`.
- Network admission: slot-8 name-copy destination conditionally overlaps the `g_szGameIniPath` address if the first five source byte pairs are nonzero. Peer-event admission copies a 20-byte scratch payload after initializing only its first byte. These are static conditional boundaries, not demonstrated runtime corruption; see `analysis/network-roster-admission.md`.
- Network input throttle: `ShouldDeferParticipantInput` has distinct session/transport gates. With `006fd50c` set in modes 2–4, a lead comparison is executed but the branch still returns “do not defer.” The compact type-6 message is annotated as type + signed lead byte + four raw sample bytes; its high-water update precedes sender lookup and append admission, so it may update even when the sample is rejected. The mark is reset, conditionally raised, and halved by throttle logic; it is not an elapsed-time or always-increasing counter. Ingress differs: the socket reader enforces its configured maximum and exact frame availability but no positive minimum; the NPS callback forwards low-word length without a local minimum check; dispatcher/handler payload extent remains unvalidated, and provider/unpacker guarantees are unresolved. A separate conditional count/frame boundary exists: the local roster producer emits1..8 entries, but the received signed roster count is copied without normalization and can feed `g_nConfiguredHumanParticipantCount`; a value above8 would make the transport-1 host-frame receiver read beyond its 32-byte sample area. This is static only; sender admission and reachability are unresolved. EOL comments mark the roster copy, published count, and receiver boundary; the count-loop annotation address is being corrected in Ghidra. Sequence-wrap/runtime invariants remain open; see issue #1 details in `analysis/detailed-analysis-notes.md`.
