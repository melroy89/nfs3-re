The local `fedata_org/menus` directory contains 135 `.mnu` files across
83 case-folded names. All 52 two-file groups contain different bytes.
In 51 groups, one file matches the author-hosted reference and the other
matches the installed Modern copy. The exception is `setup.mnu`. Its
uppercase backup matches the reference, while the lowercase backup and
installed copies have distinct SHA-256 prefixes `ed91cd1678470e35` and
`d55b7c5a1e169408`. The three backup names outside the 80-member reference
set are `mattmnu.mnu`, `racetype.mnu` and `sub.mnu`. A local case-folded
map must retain both filenames and compare content before choosing
reference inputs. Actual game or Wine path resolution remains unobserved.

Streaming `fedata/menus/setup.mnu` from the official 1.6.1 archive
confirms that it matches the lowercase backup. The installed file adds
one text control carrying a `v1.6.2` website label and replaces the
localized title field in a second text control with a literal multiplayer
title. A complete byte-line diff finds only these two edit blocks.
This distinguishes the official setup asset from the local preparation
copy, whose version label alone cannot identify an official release.
The [three-way baseline](original-modern-differences.md#1-three-way-provenance)
also identifies the installed EXE separately by SHA-256. The menu
comparison does not establish whether either control renders at runtime.

## Local pursuit vehicle archives

The installed `GAMEDATA/CARMODEL/TRAFFIC/PURSUIT` and local
backup `gamedata_org/CarModel/Traffic/PURSUIT` contain the same
six `CAR.VIV` archives, numbered `0000` through `0005`. The
whole-file SHA-256 matches for each pair. The official 1.6.1
archive lists no VIV members. In particular, both copies of
`0002/CAR.VIV` hash to
`0c217e047e25e525dc3abb3f0916685672191505db528d96fa58e924b74aef8d`.
They therefore contain the same torque-profile text, including
the empty field documented in the
[police torque report](police-torque-runtime.md).

This establishes identity between the two local asset trees.
Retail-disc provenance, original runtime selection and later
profile writes remain unverified. The
[executable comparison](og-modern-x87-precision.md#the-torque-interpolator-keeps-the-same-scaling-and-spill-points)
separately verifies the matching reader and the empty-token
conversion path.

The matching EXE path is now also verified. Both binaries retain
the police constructor prefix at `00473890..004739d0`, the
archive resolver at `0042c950..0042ca7c`, and the relevant
name-helper span at `004392b0..00439336`. For model IDs
500–505, both file-backed name tables resolve to `0000`,
`0002`, `0003`, `0004`, `0005`, and `0001`, respectively.
The shared format at `0053735c` forms the pursuit path and
the helper supplies the basename `car`. The parser handoff
at `0042c2e0..0042c310` also matches.

This connects model 501 to the same relative `0002/CAR.VIV`
path in both executables. It establishes neither the effective
asset root on a live original run nor which constructor path
that run takes.

### The retained camera loader constructs standard CAN names

Both executables retain the filename-building loop at
`0040f2bb..0040f322` and its format strings at
`005367fc` and `00536808`. It takes a caller-supplied prefix
and starts by formatting `%s%02da.can` with index zero. After
loading a present file, it increments the index, stores the
returned pointer at `00570a30 + 4 * index`, and builds the
next filename with `%s%02d.can`. It stops at a missing file or
before opening index 7.

With a `TR08` prefix and all earlier files present, this loop
requests `TR0804.CAN` at index 4. Neither format appends a
`.TRK000` suffix. A different prefix or another loader could
still open the copied files. This evidence establishes the
shared naming policy and conditional request, with actual
file opens and camera effects unobserved.

Both local trees contain the full seven-name sequence `TR0800A.CAN`
and `TR0801.CAN` through `TR0806.CAN`. A case-insensitive directory
comparison and pairwise byte checks show that all six other files in
the sequence match. The plain `TR0800.CAN` also exists in both trees
and matches, but this loop requests the `A` variant at index zero.
The paired instructions also share the early return at `0040f2c5`
when `0055e88c` is nonzero. When that gate admits loading and the
effective root resolves to either tree, the on-disk inventory has
no missing predecessor that would stop the scan before index 4.
Actual root resolution and successful opens remain unobserved.

The original and Modern caller spans `0041d975..0041d991`
and prefix builder `0041d8a0..0041d8cc` also match. On the
admitted path, the caller supplies an empty suffix to the
builder, which formats `%sTRK%03x\\Tr%02x%s` with the track
root and two copies of the selected circuit DWORD at `006fd4ac`.
The returned prefix is then passed directly to `0040f280`.
For circuit 8 this yields `TRK008/Tr08` under that root, tying
the loader's index 4 request to the changed local file.
Name resolution, the effective root, preceding file checks,
and actual camera behavior remain runtime dependencies.

In final 1.6.1, the prefix builder pushes the first path slot
`007a27b4` at `0041d8ad`. The [startup path audit](original-modern-startup-paths.md)
traces `004a6ec4` copying the first literal at `0053f42c`,
`.\gamedata\tracks\`, into that slot. The derived default
request is therefore `.\gamedata\tracks\TRK008\Tr0804.can`
relative to the process working directory. The original prefix
builder reads the same slot, populated by the
[original `install.win` reader](original-modern-language-table.md#upstream-language-selection-installwin-becomes-ini-setting).
Original startup calls `004a6e10` at `004a3d4a`. The copy
at `004a6ece..004a6efc` stores the fourth nonempty processed
record at `007a2634 + 3 * 0x80 = 007a27b4`. The local
`install.win` (SHA-256
`00787ec3b3c71303843946ad5116607baf17111f7f7632efd72bd94b2f0a7456`)
has `english`, `local`, `.\GameData\`, and
`.\GameData\Tracks\` as its first four records. With this
file and the same working directory, both routes yield the
same path components apart from case. The original takes
the root from installer data, while Modern initializes a
fixed relative root. Neither of these inputs names the
local `gamedata_org` backup. Actual working directories,
later path writes and file opens remain unobserved.

Filename index 4 is written to slot `00570a44`: the loader
increments ECX before its store at `0040f30f`. Consumers use
the first populated slot `00570a34` as their base, so their
zero-based index 4 reads that same pointer. Two matching
consumer spans show what can happen next. At
`0040f3da..0040f3fb`, the effect allocator copies the selected
pointer into a race-effect record and returns −1 if it is
null. At `0040f8e4`, the pose reader loads the selected
pointer before calling `0040f880`. The matching caller
at `00425685` supplies its resource index from context
offset `114h`.

This establishes the slot and two consumer routes. It does
not show when callers select index 4 or what visible output
the altered payload produces.

The complete pose reader at `0040f880..0040f8c7` matches
between executables. It reads a little-endian WORD at file
offset 4 and selects the last 20-byte record at offset
`8 + 20 * (count - 1)`. It copies the first three DWORDs
directly to the destination and passes the final two DWORDs
to helper `004b6ca0`.

Both local `TR0804.CAN` copies have count 51, so the reader
selects offset 1008 in either file. The three directly copied
DWORDs, displayed as signed integers without assuming units,
are `(-1210, 40968, -222822)` in the installed copy and
`(522, 53160, -179278)` in the backup. Thus the changed
asset can change the raw pose values independently of the
matched reader instructions. Actual selection of this file
and the resulting screen position remain unobserved.

The final eight record bytes are four signed little-endian
WORDs consumed by the integer rotation-matrix helper
`004b6ca0..004b6d81`. All 225 instruction bytes match between
the executables. The installed file supplies
`(-11648, -519, -525, 11497)`; the backup supplies
`(11239, 99, -31, -11920)`. For the first output DWORD,
the helper subtracts twice the square of each middle component
from `10000000h` and shifts right arithmetically by 12. This
gives 65269 for the installed file and 65530 for the backup.
Those are derived fixed-point matrix entries. This part of
the pose difference follows from the asset bytes and retained
integer operations, independently of x87 precision.
