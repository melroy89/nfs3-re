# Normal championship and Knockout terminal lifecycle

## Scope and target

This report follows the standard series path from setup, through result progression, into the post-race menu, and back to the main menu. It keeps the progression ordinal separate from the selected track ID. The inspected executable is the active installed `nfs3.exe`, SHA-256 `2a20f80465ed53d320f1a6f41c9dde2c07de0bc5525af1f23f8e6aff3e6181fb`. Static inspection only; no game, configuration, live-memory, or persistent Ghidra changes were made. The REA session was closed after inspection.

## Outer state flow

The application loop (`RunGameApplication`, `004a3db0`) starts in outer state `0x0b` and dispatches states through a jump table. State `6` or `7` calls race session `004a3690`; a normally completed race returns `0x0c`. State `0x0c` calls postgame menu routine `004732b0`, which returns its frontend menu result to the outer loop. States `6`/`7` therefore run another race, state `0x0c` presents the postgame page, and state `0x0b` enters the main-menu flow `004730d0`. Evidence: `004a3db0` assembly `ev_3386e5bea7853f429181937c5ee77e6ec851e6047d46a1d9e06243283d1eb0ad`, `004a3690` `ev_f449098573c10470c3841299fb90065da465460befcd98a861aa6580f7d91b24`, and postgame helper `004732b0` `ev_7a72f15c7790c4a366150fa7909070c75706dae6cd31ee5bcf2943f7e41e4bd3`.

The installed [`postgame.mnu`](../nfs3_decomp.rep/Electronic%20Arts/Need%20For%20Speed%20III/FEDATA/MENUS/postgame.mnu) has a `Race Again` button with `codelink=racenow` and a `Back` button with `codelink=escape Main_Menu`. The offline `racenow` handler returns action `6`; `004732b0` passes the menu-loop result back to the application loop, where `6` returns to `004a3690`. That continuation does not pass through the main-menu reset.

The Back link resolves through the ordinary menu path. In the selected executable, parser field `codelink` is type 5 (`00449240`, assembly `ev_563006b02858440a4bdf411f2b0bb2e34b1070ad4f8fba761d0430ccbab1b9f1`). The `button` row template is type 5 and has the generic item callback `00461270` at record `+0x30`; the template's `+0x40` and `+0x64` fields are zero by default (template bytes `ev_4df6f00c54dc23c907c438ccbb78c51c5bc74ff7ee3770a03cfb8149f97e599a`, type/template map `ev_5eea117cf14edf3a1b3391f0c72b8c72b9a002bf2e7aab364bfa21997d3d6abd`).

On Escape (`0x1b`), `0044a2d0` calls `0044a240`, which searches enabled type-5 rows through `0044a24c`; the helper compares each codelink's first whitespace-delimited token. Its string comparator `004429c0` copies the candidate, truncates it at whitespace, then compares it with the requested token. Thus the installed `escape Main_Menu` row matches the `escape` lookup and is selected; `0044a2d0` then calls the selected button's `+0x30` handler with the normal Enter action (`EBX=0x0d`). Evidence: `0044a2d0` `ev_e38fb8b1624dc57b48213e742f840d5edcf41feebe2d34874388819a45a70183`, `0044a240` `ev_a894440e277b54cff07ae5a2872e46a747ee97e5705f81fc589f1b5da36b9056`, `0044a24c` `ev_76fa0d0f14629387f4b9324a646ce27e6d154ee2054367ea2d265960dcc0bf75`, and `004429c0` `ev_9f449d2546bbbbcc4672bd96d9280103ce9f50380edb5edcb32829a2b0cbd2c3`.

For this Back row, the generic handler `00461270` sees no row `+0x64` callback, does not match its built-in `racenow` or `exitprogram` tokens, and takes its zero-`+0x40` fallback, returning menu action `3` (`ev_e9090424ea4c70962abfe76b6a515a2d3c459796e07e9862a7f9f95dd9568848`). This row has neither an optional callback nor a menu-target field in the installed resource; the button template supplies zero for the tested fields. Postgame wrapper `004732b0` explicitly clears EDX before calling the menu loop. `0044b230` therefore establishes its root descriptor as `006040d0`; when action `3` reaches the root-menu boundary, the loop sets its return value to `0x0b` and exits (`0044b230` assembly `ev_afe4ea07ca37907afb48d2526d0e37d57f480104e26bde14f9364ef5f2f8601b`, wrapper `004732b0` assembly `ev_7a72f15c7790c4a366150fa7909070c75706dae6cd31ee5bcf2943f7e41e4bd3`). The outer application switch maps `0x0b` to `004730d0`, whose entry clears both series-state regions (`004a3db0` `ev_3386e5bea7853f429181937c5ee77e6ec851e6047d46a1d9e06243283d1eb0ad`; reset `004730d0` `ev_141481d6381e21d6ada2ea280ff4ef2798e28021b78a73a2b827716fbefa9fcc`). This completes the static ordinary Back → root-menu action `0x0b` → main-menu reset chain. It is static evidence, not an interactive menu observation.

## Reset points

At entry to `004730d0`, the main-menu path zero-fills two separate series state regions: `0x50` bytes starting at `006fd3bc` and `0x62` bytes starting at `006fd40c` (`0047319f–004731c6`). These include the Knockout and mode-one progression words, respectively. The main-menu entry resets both series records before it enters its menu flow, including the application's initial state-`0x0b` entry. Evidence: `004730d0` assembly `ev_141481d6381e21d6ada2ea280ff4ef2798e28021b78a73a2b827716fbefa9fcc`.

Race Again takes the `6`/`7` race path and retains those series records. Returning to the main-menu state runs `004730d0` and clears them. The postgame function itself resets `006fd3a0` (playback mode) but does not clear either series progression word.

## Mode-one series (eight-track sequence)

The mode-one progression ordinal is the WORD at `006fd40c`. `BuildRaceModeOneRoster` (`00474310`) loads the DWORD at `006fd40a`, shifts it right by 16, and uses that high WORD as the index into the eight-DWORD map at `0055d004`; it stores the selected map value in `006fd4ac`, the current track ID. The installed active executable has map values `0,1,2,3,4,5,6,7` at `0055d004..0055d020` (read evidence `ev_dd783f803c652bb036818597423976755125d1c7bfc4699f245ccc7c31d06000`); the final map element at `0055d020` is DWORD `7` (`ev_5c0be97fb2d9b219f7b0ec73a19a6a94c8cb5d4bbf9702ec618c7ef1eb655578`). The shared selected-track ID is not the progression ordinal.

Race result pipeline `00455410` runs only under its enclosing race-result gate and dispatches mode `1` to `00455070` (`ev_6c526022d030edf0f3db2df8adfd7fdae682d31c751c85d31d0d71160790304b`). That updater first returns if `004cef80` reports a blocking state; on its continuing path it updates per-player round/total scores and the order table, then increments WORD `006fd40c` at `00455129` (`ev_5a0e625062537599bff0de1c5bbff9bb9de19b9fb8a65eaef80a9750fac80757`). There is no endpoint comparison in this updater. For the normal eight-track sequence, the selected ID on round seven is `7`; if the result updater's state gate allows the update, the progression ordinal advances from `7` to `8` before postgame.

## Knockout series (seven generated tracks)

Knockout progression is the WORD at `006fd3bc`; it indexes the seven-entry list at `006fd3fe..006fd40a`. `BuildRaceModeTwoRoster` (`00473ee0`) generates this list only while progression is zero, then uses the current progression value to choose the next list entry. The generator (`00473ac0`) selects seven ascending survivors from candidate track IDs `0..8`, excluding two IDs from one of the `0..3` or `4..7` groups; ID `8` is never removed and is therefore list entry `6` whenever generation completes. Existing bounded generation evidence is summarized in [`series-terminal-menu-contract.md`](series-terminal-menu-contract.md#mode2-generated-endpoint-and-participant-retention); fresh active-code evidence for the builder and generator is `ev_7a65a2310a93252c263168e82acdc670667aa3f6e212a7880036d215e116b074` and `ev_8117f2ba3b41d7891afc6db5079d8df74704d48efe7fa3c585db4d0923796971`.

Mode `2` result processing dispatches to `EliminateLastEligibleResultAndUpdateOrder` (`00455140`). When called, it builds the ordering/elimination results and increments WORD `006fd3bc` unconditionally at `00455200` (`ev_0347d8d415ab20a9152e277adea4a61e6f68c3637f6b00f0aef72adb5eaf6a0d`). Thus the last generated track ID is `8` at progression index `6`; after its result update the progression word becomes `7`, before postgame.

## Terminal policy and normal continuation

`GetPostgameRaceAgainEligibility` (`004cf090`) uses the current track ID at `006fd4ac`, not the progression ordinal. For mode `1`, it compares that ID with the last mode-one map entry `DWORD[0055d020]` (`7`). For mode `2`, it compares the ID against the high WORD of `DWORD[006fd408]`, which is `WORD[006fd40a]`—the final generated Knockout list value (`8`). On endpoint equality, the helper clears its eligibility return. It also applies the result-record queries and network/abort conditions. It does not write either progression field or reset a series. Evidence: `004cf090` assembly `ev_d36f0c844d6fbfe3011f43dac28722cc01802acf714ab266febcfda52beaeab9`.

Offline postgame initialization calls this gate for the `racenow` entry and ORs disabled bit `0` into its entry flags when the gate returns zero (`0044f2dc–0044f2e5`; original active bytes confirmed by disassembly). This is the normal terminal-menu result: Race Again is unavailable at the endpoint, while the page provides its Back/Main Menu action. The ordinary route returns to postgame after result handling; it does not automatically start another round or reset progression. On entering the main-menu state, `004730d0` performs the reset described above. No disabled-entry bypass or exceptional-state behavior is claimed here.
